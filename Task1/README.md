# Архитектура данных FinUnion Group после объединения с RetailBank: анализ данных, сущностей и хранилищ

Комплект документов описывает ключевые данные объединённой организации, их логическую модель, классификацию, стратегию хранения и сопоставление с референсной моделью BIAN. Результаты служат основой для единого профиля клиента, матрицы мастер-систем, MDM и целевой платформы данных.

## Контекст

FinUnion Group приобрела региональный RetailBank. У каждой организации собственные CRM, АБС, карточный процессинг, кредитная система, DWH и BI. Одни и те же клиенты заведены в обеих организациях с разными идентификаторами, форматы данных и справочники не согласованы, отчётность строится раздельно.

Ограничения: без остановки клиентских сервисов, без одномоментной замены систем RetailBank, с сохранением корректности финансовых данных и защитой ПДн, без аналитической нагрузки на операционные системы, с трассируемостью происхождения данных. Промежуточный результат — через 3 месяца, целевой — через 12 месяцев.

## Ключевые решения

| № | Решение | Обоснование |
| --- | --- | --- |
| 1 | Единый клиентский идентификатор выдаёт только MDM, локальные идентификаторы связываются через кросс-ссылки | Позволяет получить единый профиль без изменения legacy-систем RetailBank |
| 2 | Стартовый список сущностей уточнён: «Транзакция» заменена на «Операцию», «Платёж» отделён от «Операции», «Справочник» разделён на сегмент, подразделение и тариф, добавлены кросс-ссылка, связь клиентов и документ клиента | Устраняет двусмысленность терминов и покрывает задачи сопоставления, кредитного риска и законности обработки ПДн |
| 3 | Аналитика получает данные через CDC и Data Lakehouse, а не запросами к OLTP | Разделение операционной и аналитической нагрузки |
| 4 | Графовая БД и поисковый движок — производные хранилища, не мастер-системы | Обоснованы конкретными сценариями (связи заёмщиков и антифрод, поиск в КЦ), но данные ведутся в MDM и CRM |
| 5 | Домены данных строятся по сервисным доменам BIAN | Единая терминология, однозначные границы владения, основа для data products |
