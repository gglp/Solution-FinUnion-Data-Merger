# Потоки данных промежуточного состояния

Документ описывает потоки данных между системами FinUnion, RetailBank и новыми компонентами через 3 месяца после начала работ: что передаётся, какие действия выполняются с данными, в каком режиме и зачем нужен каждый поток. Номера потоков едины для этого документа, диаграммы и data-flow-management.md.

DFD уровня 0 (контекстная) приведена в разделе 5, исходный код — [diagrams/dfd-level0-intermediate.puml](diagrams/dfd-level0-intermediate.puml).

## 1. Компоненты промежуточного состояния

| № | Компонент | Состав через 3 месяца | Роль в потоках |
| --- | --- | --- | --- |
| 1 | Integration Layer | ESB FinUnion; CDC-коннекторы к базам RB Core, RB CRM; брокер событий; API-адаптеры только для чтения к RB Core, RB Cards, RB Loans; реестр схем | Единая точка обмена. Проверка схемы и контракта сообщений, маршрутизация. Заменяет point-to-point-интеграции RB для новых потоков, существующие потоки RB не трогает |
| 2 | MDM Customer Hub | Реестровая модель: единый клиентский идентификатор, кросс-ссылки, вычисляемая золотая запись, таблицы соответствия справочников FU и RB | Мастер единого идентификатора и золотой записи. Стандартизация, сопоставление, обогащение |
| 3 | DWH | FU DWH, расширенный слоем данных RB и измерениями из MDM | Консолидированная управленческая отчётность, регуляторная отчётность FinUnion |
| 4 | BI | FU BI | Единая управленческая отчётность и дашборды |
| 5 | DataHub | Каталог данных: глоссарий, владельцы, lineage, метрики качества для критичных сущностей | Прозрачность происхождения данных и качества |
| 6 | RB DWH | Без изменений | Регуляторная отчётность RetailBank как отдельного юридического лица до реорганизации; источник истории для DWH |

Допущение: в течение первых 3 месяцев RetailBank остаётся отдельным юридическим лицом и сдаёт регуляторную отчётность самостоятельно. Поэтому регламентный контур RB DWH не меняется, а единая отчётность строится как управленческая.

## 2. Действия с данными

| № | Действие | Значение в контексте потоков |
| --- | --- | --- |
| 1 | Create | Создание новой записи в приёмнике |
| 2 | Read | Чтение без изменения: извлечение для загрузки, запрос по API |
| 3 | Update | Изменение существующей записи |
| 4 | Delete | Логическое удаление: расклейка ошибочного сопоставления, отзыв согласия, деперсонализация по истечении срока хранения. Физическое удаление финансовых данных запрещено |
| 5 | Enrich | Дополнение записи данными другой системы: единый идентификатор, стандартизованный адрес, сопоставленный код справочника |
| 6 | Validate | Проверка формата, обязательности, контрольных сумм, сверка итогов |
| 7 | Aggregate | Расчёт показателей и витрин, формирование отчётности |

## 4. Потоки данных

| № | Источник | Приёмник | Передаваемые сущности | Действие | Режим обмена | Обоснование |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | FU CRM | MDM Customer Hub (через ESB) | Клиент | Create, Update | Асинхронный, события | Формирование золотой записи по клиентам FinUnion в момент изменения |
| 2 | RB CRM | MDM Customer Hub (через CDC) | Клиент | Create, Update | CDC | RB CRM не умеет публиковать события; CDC позволяет получать изменения без доработки системы и без нагрузки запросами |
| 3 | FU Core | MDM Customer Hub (через CDC) | Клиент (карточка контрагента АБС) | Create, Update | CDC | Документы и ИНН в АБС подтверждены при идентификации в офисе, это приоритетный источник для золотой записи |
| 4 | RB Core | MDM Customer Hub (через CDC) | Клиент (карточка контрагента АБС) | Create, Update | CDC | Клиенты RB, открывшие счёт в офисе, могут отсутствовать в RB CRM |
| 5 | FU Cards, RB Cards, FU Loans, RB Loans | MDM Customer Hub | Клиент (держатели, заёмщики), Связь клиентов | Update | Batch, ежедневно | Полнота кросс-ссылок по всем системам; связи поручителей и созаёмщиков для консолидации |
| 6 | MDM Customer Hub | FU CRM, RB CRM (через ESB и адаптер RB) | Единый клиентский идентификатор, золотая запись | Update, Enrich | Асинхронный, события | Менеджеры видят единый идентификатор и эталонные атрибуты. В RB CRM передаётся только идентификатор: менять процессы RB в переходный период не требуется |
| 7 | MDM Customer Hub | FU Core (через ESB) | Единый клиентский идентификатор | Enrich | Асинхронный, события | Связь учётных данных FU с единым клиентом для отчётности и обслуживания |
| 8 | MDM Customer Hub | FU CRM, RB CRM, FU Core, DWH | Кросс-ссылка, признак согласия | Delete (логическое) | Асинхронный, события | Исправление ложных склеек и отзыв согласий должны распространяться на всех потребителей |
| 9 | FU CRM | MDM Customer Hub (через ESB) | Клиент | Read | Синхронный, API | Поиск клиента и проверка на дубль до создания карточки; доступ к профилю клиента RB |
| 10 | FU CRM | RB Core, RB Cards, RB Loans (через API-адаптеры) | Счёт, Карта, Кредит, Договор | Read | Синхронный, API | Единая картина продуктов клиента RB для менеджеров FinUnion без миграции данных |
| 11 | FU CRM | FU Core, FU Cards, FU Loans (через ESB) | Договор, Счёт, Карта, Кредит | Create | Синхронный | Клиенты RB получают продукты FinUnion в системах FU с единым идентификатором |
| 12 | FU Core, RB Core, FU Cards, RB Cards, FU Loans, RB Loans, FU CRM, RB CRM | MDM Customer Hub | Продукт, Тариф, Подразделение, Клиентский сегмент | Read, Validate, Enrich | Batch, ежедневно | Таблицы соответствия справочников FU и RB для единой отчётности |
| 13 | FU Core, FU Cards, FU Loans, FU CRM | DWH (через ESB) | Договор, Счёт, Карта, Кредит, Операция, Платёж, Обращение | Read, Validate | Batch, ежедневно | Существующие загрузки FU DWH сохраняются без изменений |
| 14 | RB Core | DWH (через CDC и брокер событий) | Договор, Счёт, Операция, Платёж | Read, Validate | CDC, накопление в промежуточном слое, загрузка ежедневно | Аналитика RB перестаёт нагружать АБС прямыми выгрузками; данные RB попадают в консолидированное DWH |
| 15 | RB Cards, RB Loans, RB CRM | DWH (через Integration Layer) | Карта, Кредит, Обращение | Read, Validate | Batch, ежедневно | Полный состав данных RB в консолидированной отчётности |
| 16 | MDM Customer Hub | DWH | Золотая запись, Кросс-ссылка, таблицы соответствия справочников | Enrich | Batch, ежедневно | Единые измерения: один клиент, продукт, подразделение для данных FU и RB |
| 17 | RB DWH | DWH | Исторические данные RB, контрольные итоги | Read, Validate | Batch: история — однократно, итоги — ежедневно | История для сравнимых отчётов; сверка консолидированных данных с отчётностью RB |
| 18 | DWH | BI | Витрины по клиентам, счетам, продуктам, операциям | Aggregate | Batch, ежедневно | Единая управленческая отчётность |
| 19 | DWH | Банк России | Регуляторная отчётность FinUnion | Aggregate | Batch, по графику отчётных форм | Внешний потребитель; данные RB включаются после реорганизации |
| 20 | RB DWH | Банк России | Регуляторная отчётность RetailBank | Aggregate | Batch, по графику отчётных форм | Без изменений до реорганизации RetailBank |
| 21 | FU Cards → FU Core, RB Cards → RB Core | АБС своей организации | Операция (карточная) | Create | Онлайн и пакетный клиринг | Существующий операционный поток, показан для полноты |
| 22 | FU Loans → FU Core, RB Loans → RB Core | АБС своей организации | Операция (по кредиту) | Create | Batch, ежедневно | Существующий операционный поток, показан для полноты |
| 23 | Integration Layer, MDM Customer Hub, DWH | DataHub | Метаданные, lineage, результаты проверок качества | Read | Batch ежедневно и по событию изменения схемы | Трассируемость происхождения данных и прозрачность качества |
| 24 | RB Core, RB Cards, RB Loans | RB DWH | Договор, Счёт, Карта, Кредит, Операция | Read | Batch, ежедневно | Существующие выгрузки для регуляторной отчётности RB; выводятся после переноса отчётности |
