# Технологическая дорожная карта

Документ распределяет технологии и подходы целевой архитектуры данных по зонам готовности и объясняет, почему каждая технология попала в свою зону.

## 1. Зоны

| № | Зона | Значение |
| --- | --- | --- |
| 1 | Adopt | Используется в промышленной эксплуатации, обязательна для новых решений |
| 2 | Trial | Внедряется на ограниченной области с проверкой на реальных данных, расширяется после подтверждения результатов |
| 3 | Assess | Изучается и оценивается для конкретных сценариев, решение о внедрении — после 12 месяцев |
| 4 | Hold | Не используется для новых решений, выводится или сохраняется только до замены |

## 2. Распределение технологий

| № | Зона | Что включить | Почему |
| --- | --- | --- | --- |
| 1 | Adopt | MDM | Без золотой записи и единого клиентского идентификатора невозможны единый профиль, сопоставление клиентов и корректная отчётность; нужен с первых 3 месяцев |
| 2 | Adopt | Apache Kafka, Debezium, реестр схем | Основа событийной интеграции и CDC; позволяет получать данные из систем RB без их доработки и без нагрузки запросами |
| 3 | Adopt | Apache Airflow, dbt | Зрелые инструменты оркестрации и преобразований; нужны уже для DWH промежуточного состояния и переносятся в целевое без изменений |
| 4 | Adopt | DataHub | Каталог, lineage и владельцы требуются для трассируемости с первых потоков; без каталога нельзя управлять миграцией данных |
| 5 | Adopt | PostgreSQL для DWH промежуточного состояния | Знакомая технология, быстрый запуск единой управленческой отчётности через 3 месяца |
| 6 | Adopt | API Gateway и ESB FinUnion | Действующий интеграционный слой FU; расширяется на партнёров RB, замена в период миграции увеличила бы риск |
| 7 | Adopt | S3-совместимое объектное хранилище | Основа Lakehouse и архивов выводимых систем; технология проста и зрела |
| 8 | Trial | Apache Iceberg, Trino, Apache Spark | Основа Lakehouse; новая для команды технология, поэтому начинается с пилота на истории карточных операций и после подтверждения производительности и эксплуатации становится основным путём данных в DWH |
| 9 | Trial | MPP-СУБД, совместимая с PostgreSQL (Greenplum / Arenadata DB) | Целевое DWH; требует нагрузочного тестирования на объёмах объединённого банка и параллельной работы с промежуточным DWH до переключения отчётности |
| 10 | Trial | Доменные data-продукты | Элемент Data Mesh; запускается для пяти продуктов (Customer 360, счета и остатки, карточные операции, кредитный портфель, обращения), расширение — после оценки зрелости доменов |
| 11 | Trial | Контракты данных | Формализация схем и SLA потоков между доменами; вводится для потоков клиентских данных и data-продуктов |
| 12 | Assess | Графовая БД | Полезна для связей клиентов, групп связанных заёмщиков и антифрода, но не требуется для целевого результата; оценивается на данных связей клиентов из MDM |
| 13 | Assess | Apache Flink | Потоковая обработка с низкой задержкой для антифрода; Spark Structured Streaming покрывает текущие потребности |
| 14 | Assess | Поисковый движок (OpenSearch) | Нечёткий поиск клиентов и полнотекстовый поиск по обращениям в контактном центре; оценивается после консолидации CRM |
| 15 | Assess | Хранилище признаков для машинного обучения | Повторное использование признаков скоринга и антифрода; оценивается после накопления истории в Lakehouse |
| 16 | Assess | Полномасштабный Data Mesh | Требует зрелости доменов и федеративного управления; оценивается по итогам работы пяти data-продуктов |
| 17 | Hold | Point-to-point-интеграции RB | Нет единого подхода к потокам, нет контроля и lineage; заменяются Integration Layer и Kafka |
| 18 | Hold | Прямые аналитические выгрузки из операционных систем | Нагружают АБС и обходят контроль качества; заменяются CDC |
| 19 | Hold | RB CRM, RB Cards, RB DWH, RB BI | Дублируют системы FU; новые разработки на них запрещены, выводятся по плану миграции |
| 20 | Hold | Частичный FU Data Lake | Децентрализованное хранение неструктурированных данных без каталога; данные переносятся в Lakehouse |
| 21 | Hold | Ручные сверки и отчёты в электронных таблицах | Не обеспечивают воспроизводимость и lineage; заменяются проверками в dbt и витринами DWH |
| 22 | Hold | Развитие DWH на PostgreSQL сверх промежуточного состояния | Ограничен масштабируемостью одного экземпляра; новые модели создаются с расчётом на целевое DWH |
