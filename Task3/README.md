# Архитектура данных FinUnion Group после объединения с RetailBank: целевая архитектура и аналитическая платформа

Комплект документов описывает целевую архитектуру данных объединённого банка через 12 месяцев: операционные системы и хранилища, аналитическую платформу, пайплайны данных, аналитическую модель, доменные data-продукты и модель управления данными. Опирается на ранее определённые ключевые сущности, мастер-системы, владение данными и потоки промежуточного состояния.

## Ключевые решения

| № | Решение | Обоснование |
| --- | --- | --- |
| 1 | Гибридная архитектура: DWH + Data Lakehouse + элементы Data Mesh | DWH обеспечивает строгую регламентированную отчётность, Lakehouse — большие исторические и событийные данные, data-продукты — доменное владение |
| 2 | Через 3 месяца — DWH на PostgreSQL, через 12 месяцев — DWH на MPP-СУБД, совместимой с PostgreSQL | Быстрый промежуточный результат и перенос моделей dbt и SQL без переписывания при росте объёмов |
| 3 | Lakehouse на Apache Iceberg с доступом через Trino и обработкой Spark | Открытый формат, транзакционная запись CDC, история таблиц, общий доступ для разных движков |
| 4 | DWH загружается из очищенного слоя Lakehouse | Один путь данных из операционных систем, единая точка очистки и сверки |
| 5 | Отчётность регулятору и подписываемые отчёты — только из DWH | Воспроизводимость и контроль регламентированной отчётности |
| 6 | Оркестрация — Airflow и dbt, каталог и lineage — DataHub | Управляемые пайплайны и трассируемость происхождения данных |
