# Владение данными

Документ определяет роли и правила владения ключевыми данными: кто отвечает за данные, кто следит за их качеством, какие системы их создают и потребляют, кто вправе их изменять и какие проверки обязательны.

## 1. Роли

| № | Роль | Ответственность |
| --- | --- | --- |
| 1 | Владелец данных (Data Owner) | Руководитель бизнес-подразделения. Утверждает определение сущности, правила доступа, требования к качеству и мастер-систему. Принимает решения о предоставлении доступа к данным критичной и высокой категорий |
| 2 | Распорядитель данных (Data Steward) | Эксперт бизнес-подразделения или Data Office. Ведёт правила качества, разбирает инциденты качества, подтверждает сомнительные сопоставления, поддерживает описание в каталоге данных |
| 3 | Производитель (Producer) | Система или команда, создающая данные. Отвечает за соблюдение контракта данных при публикации |
| 4 | Потребитель (Consumer) | Система или команда, использующая данные. Не изменяет полученные данные и не публикует их как эталонные |
| 5 | Технический владелец системы | ИТ-команда системы. Обеспечивает доступность, мониторинг потоков, исполнение технических проверок |
| 6 | Data Office | Методология управления данными, каталог данных, единые правила качества, координация распорядителей |
| 7 | Совет по данным | Представители владельцев данных, Data Office, ИТ, ИБ. Утверждает матрицу мастер-систем, разрешает конфликты владения |

Владение определяется по сервисным доменам BIAN: у сервисного домена один владелец данных.

## 3. Правила изменения и качества

| № | Сущность | Правила изменения | Правила качества |
| --- | --- | --- | --- |
| 1 | Клиент | Создание — в CRM своей организации или в АБС при открытии счёта. Единый идентификатор присваивает только MDM. Изменение документов и ИНН — только при подтверждённой идентификации клиента. Склейка и расклейка — только распорядителем в MDM | Обязательные атрибуты по типу клиента; контрольные суммы ИНН и СНИЛС; формат телефона E.164; адрес по ГАР; проверка на дубли до создания; полнота и актуальность не старше срока переидентификации |
| 2 | Кросс-ссылка идентификаторов | Только MDM: автоматически по правилам сопоставления или распорядителем при ручной проверке. Ручные изменения — с подтверждением второго сотрудника | Одна локальная запись связана ровно с одним единым идентификатором; доля автоматических сопоставлений и ложных склеек; срок разбора очереди |
| 3 | Связь клиентов | В системе-производителе по документу-основанию. В целевом состоянии — в MDM | Обязательный тип связи и период действия; запрет связи клиента с самим собой; доля владения от 0 до 100 % |
| 4 | Клиентский сегмент | Справочник — владелец данных по согласованию с Data Office. Отнесение клиента — по правилам, ручное изменение запрещено | Каждый клиент отнесён ровно к одному сегменту; каждый сегмент RB сопоставлен сегменту FU |
| 5 | Подразделение | Сеть продаж по приказу о реорганизации или открытии и закрытии офиса | Уникальность кода с учётом организации; дата закрытия для закрытых; непрерывность иерархии |
| 6 | Продукт | Продуктовый комитет. Вывод продукта из продажи не удаляет запись | Уникальный код; каждый продукт RB сопоставлен продукту FU или помечен как не имеющий аналога; статус и даты действия |
| 7 | Тариф | Новая версия по решению продуктового комитета; изменение действующей версии запрещено | Непересекающиеся периоды версий; полнота параметров; соответствие тарифа в учётной системе опубликованному |
| 8 | Договор | Только мастер-система по продукту. Расторжение — через смену статуса | Связь с клиентом, у которого есть единый идентификатор; связь с продуктом и тарифом; уникальность номера с учётом организации |
| 9 | Счёт | Только АБС. Закрытие — через смену статуса, физическое удаление запрещено | Контрольный ключ номера счёта; соответствие балансового счёта типу; связь с договором; сверка остатков АБС и DWH |
| 10 | Карта | Только процессинг. Блокировка — также по запросу из каналов через процессинг | Наличие токена вместо номера карты вне процессинга; связь со счётом; допустимые переходы статусов |
| 11 | Кредит | Только кредитная система; ручные корректировки — по распоряжению с журналом | Сверка задолженности кредитной системы и АБС; полнота графика; корректность дней просрочки |
| 12 | Операция | Неизменяема после проведения. Исправление — только сторнирующей операцией | Контрольные суммы и количество записей при передаче; баланс дебета и кредита; сверка с выписками |
| 13 | Платёж | Клиент или сотрудник до исполнения; после исполнения — только смена статуса мастер-системой | Валидность реквизитов получателя; лимиты; антифрод-проверка до исполнения |
| 14 | Обращение | Сотрудники контактного центра и офисов в CRM | Привязка к клиенту и единому идентификатору; тип и тема из классификатора; соблюдение нормативного срока |
| 15 | Документ клиента | Загрузка — сотрудники офисов и каналы; удаление — только по истечении срока хранения или отзыву согласия, по регламенту | Связь с клиентом; контрольная сумма файла; наличие действующего согласия на обработку ПДн до передачи данных клиента RB в системы FU |

## 4. Порядок разрешения конфликтов

| № | Ситуация | Порядок |
| --- | --- | --- |
| 1 | Расхождение атрибута клиента между FU и RB | Применяется правило приоритета источников MDM; спорные случаи — распорядителю клиентских данных |
| 2 | Сомнительное сопоставление клиентов | Ручная проверка распорядителем в нормативный срок; до решения записи не склеиваются |
| 3 | Спор о владельце сущности | Решение Совета по данным на основе границ сервисных доменов BIAN |
| 4 | Инцидент качества в критичных данных | Распорядитель фиксирует инцидент, владелец потока останавливает публикацию, владелец данных принимает решение о корректировке |
