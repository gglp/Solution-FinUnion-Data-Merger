# Управление потоками данных

Документ задаёт для каждого потока промежуточного состояния формат, частоту, тип обмена, SLA, владельца, контроль качества, требования к безопасности и способ мониторинга. Номера потоков соответствуют data-flows.md.

## 1. Общие правила

| № | Правило | Содержание |
| --- | --- | --- |
| 1 | Контракт данных | Каждый поток описан контрактом: схема в реестре схем, состав сущностей и атрибутов, SLA, владелец, правила качества. Изменение схемы источника без обновления контракта запрещено |
| 2 | Канонический формат | События и API используют каноническую модель данных (logical-data-model.md); преобразование из форматов систем выполняется в Integration Layer |
| 3 | Владелец потока | Владелец данных передаваемой сущности. Отвечает за SLA и решения при инцидентах; техническое сопровождение — команда Integration Layer или DWH |
| 4 | SLA | Для асинхронных потоков и CDC — задержка от изменения в источнике до появления в приёмнике; для синхронных — время ответа (95-й процентиль) и доступность; для пакетных — срок готовности данных |
| 5 | Повторная обработка | Асинхронные потоки идемпотентны: каждое сообщение имеет ключ и версию, повторная доставка не создаёт дублей. Ошибочные сообщения направляются в очередь ошибок |
| 6 | Остановка при сбое качества | Для критичных данных (счета, операции, кредиты) загрузка в витрины останавливается при нарушении контрольных итогов |

## 3. Требования к безопасности и мониторинг

| № | Поток | Требования к безопасности | Способ мониторинга |
| --- | --- | --- | --- |
| 1 | FU CRM → MDM | TLS; сервисная учётная запись с правом публикации в одну тему; ПДн в событии в зашифрованном виде на уровне брокера | Задержка доставки, глубина очереди, очередь ошибок; метрики дублей в MDM |
| 2 | RB CRM → MDM | Учётная запись CDC только на чтение журнала изменений; TLS; маскирование ПДн в логах коннектора | Задержка CDC, состояние коннектора, ежедневная сверка количества записей |
| 3 | FU Core → MDM | Чтение журнала изменений только по таблицам клиентов; TLS | Задержка CDC, состояние коннектора, сверка количества |
| 4 | RB Core → MDM | Как поток 3; отдельный сетевой сегмент для коннекторов RB | Задержка CDC, нагрузка на RB Core, сверка количества |
| 5 | Процессинг и кредитные системы → MDM | Шифрование файлов; номер карты не передаётся, только токен | Факт и время поступления файла, контрольное количество |
| 6 | MDM → CRM | TLS; подпись сообщений; передаются только атрибуты, разрешённые для CRM | Подтверждения доставки, доля записей без идентификатора |
| 7 | MDM → FU Core | TLS; передаётся только идентификатор | Подтверждения доставки, очередь ошибок |
| 8 | MDM → потребители (Delete) | Подпись сообщений; журнал исполнения хранится по сроку хранения согласий | Отчёт о необработанных событиях удаления старше SLA |
| 9 | FU CRM → MDM (API) | mTLS; авторизация по роли пользователя (передача контекста пользователя); аудит каждого запроса профиля | Время ответа, доля ошибок, доступность; аномальное количество запросов от одного пользователя |
| 10 | FU CRM → системы RB (API) | mTLS; только чтение; проверка признака согласия до выдачи данных; маскирование номеров счетов и карт; аудит | Время ответа, нагрузка на системы RB, срабатывания ограничения частоты |
| 11 | FU CRM → продуктовые системы FU | Действующие требования ESB; электронная подпись документов клиента | Действующий мониторинг ESB; доля отказов из-за отсутствия идентификатора или согласия |
| 12 | Справочники → MDM | Шифрование файлов при передаче | Факт поступления; отчёт о несопоставленных кодах распорядителю |
| 13 | FU-системы → DWH | Шифрование при передаче и хранении; доступ к детальному слою по ролям | Время готовности слоя, контрольные итоги, отчёт сверок |
| 14 | RB Core → DWH (CDC) | Учётная запись только на чтение журнала; шифрование в брокере; разделение тем по категориям данных | Задержка CDC, полнота захвата, нагрузка на RB Core |
| 15 | RB-системы → DWH | Шифрование файлов; номер карты только токеном | Факт и время поступления, контрольные итоги |
| 16 | MDM → DWH | Шифрование; ПДн в детальном слое доступны ограниченным ролям | Время готовности, доля несвязанных записей |
| 17 | RB DWH → DWH | Шифрование; однократная загрузка истории под контролем ИБ | Отчёт расхождений итогов |
| 18 | DWH → BI | Витрины без прямых ПДн либо с маскированием; RBAC на уровне строк по подразделениям | Время публикации витрин, статус сверок, использование отчётов |
| 19 | DWH → Банк России | Защищённый канал и электронная подпись по требованиям Банка России | Календарь отчётности, статус формирования и отправки форм |
| 20 | RB DWH → Банк России | Действующие требования RB | Календарь отчётности RB |
| 21 | Процессинг → АБС | Требования платёжных систем и PCI DSS в контуре процессинга | Действующий мониторинг процессинга |
| 22 | Кредитные системы → АБС | Действующие требования | Действующие сверки |
| 23 | Компоненты → DataHub | Метаданные без значений ПДн; образцы данных в каталоге отключены для критичных наборов | Полнота каталога, свежесть метаданных |
| 24 | Системы RB → RB DWH | Действующие требования | Время окна выгрузки, нагрузка на RB Core |
